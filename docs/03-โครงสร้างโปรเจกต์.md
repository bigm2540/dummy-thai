# เอกสารโครงสร้างโปรเจกต์ — เกมดัมมี่กินเงินไทย

> **เฟส 0 (ต่อ)** — ออกแบบโครงสร้างไฟล์/โฟลเดอร์ + เครื่องมือ ก่อนเขียนโค้ด
> ยังไม่สร้างไฟล์จริง — เป็นพิมพ์เขียวของโปรเจกต์
> อ้างอิง: [01-กติกาเกม.md](01-กติกาเกม.md), [02-ออกแบบ-data-model.md](02-ออกแบบ-data-model.md)

---

## 0. หลักการสำคัญ

1. **แยก game logic ออกจากเน็ต/หน้าจอ** — โฟลเดอร์ `server/game/` เป็นโค้ดบริสุทธิ์ (ไม่ import socket/express) → **ทดสอบได้โดยไม่ต้องมีเน็ต** (เฟส 1 ขั้นแรก)
2. **Server เป็นเจ้าของความจริง (authoritative)** — game logic รันที่เซิร์ฟเวอร์เท่านั้น client แค่ส่ง action + วาดหน้าจอ
3. **เริ่มเรียบง่าย** — ภาษา JavaScript ล้วน, client เป็น HTML/CSS/JS ธรรมดา (ยังไม่ใช้ React)

## 2. หน้าที่ของแต่ละไฟล์หลัก

### 🖥️ server/game/ (game logic บริสุทธิ์ — เทสได้โดยไม่ต้องมีเน็ต)
| ไฟล์ | หน้าที่ | กติกาที่เกี่ยว |
|------|--------|---------------|
| `constants.js` | นิยาม Suit/Rank/MeldType ฯลฯ, ระบุสเปโต (2♣/Q♠) | ข้อ 2, 11 (data model) |
| `deck.js` | สร้างไพ่ 52 ใบ, สับ, แจก 7 ใบ, เปิดไพ่หัว | กติกา §4 |
| `meld.js` | ตรวจว่าเป็นตอง/เรียงถูกไหม (A สูง), กฎเก็บกอง | กติกา §5.1, §6 |
| `scoring.js` | แต้มสุทธิ, จัดอันดับเสียน้อย/กลาง/มาก, คะแนน, โบนัส, บทลงโทษ | กติกา §7-9 |
| `round.js` | คุมลำดับตา (จั่ว/เกิด/ฝาก/ทิ้ง/น็อค), ทิศทาง (โง่กลับทิศ), ตรวจ action ถูกกติกา | กติกา §5, §7 |
| `playerView.js` | แปลง state เต็ม → view ของผู้เล่นแต่ละคน (ซ่อนมือคนอื่น+กองจั่ว) | data model §14.4 |

### 🖥️ server/ (เน็ต + ห้อง)
| ไฟล์ | หน้าที่ |
|------|--------|
| `index.js` | เปิดเซิร์ฟเวอร์ HTTP, เสิร์ฟไฟล์ client, ตั้ง Socket.IO |
| `room/roomManager.js` | สร้างห้อง/รหัสห้อง, เข้าห้อง, เริ่มเกม, หน้าสรุปรอบ, ปิดห้อง |
| `socket/handlers.js` | ฟัง event (สร้างห้อง/เข้าห้อง/action ในเกม) → เรียก game logic → emit view กลับ |

### 📱 client/
| ไฟล์ | หน้าที่ |
|------|--------|
| `index.html` | โครงหน้าเว็บ (หน้าล็อบบี้ + หน้าเล่น + หน้าสรุป) |
| `style.css` | จัดหน้าตา, ไพ่กดง่ายบนมือถือ |
| `js/socket.js` | เชื่อมต่อ + รับส่งข้อมูลกับเซิร์ฟเวอร์ |
| `js/render.js` | วาดไพ่/โต๊ะ/มือ/ปุ่ม จาก PlayerView ที่ได้รับ |
| `js/app.js` | ตัวกลางผูก socket ↔ render, จัดการการกดของผู้เล่น |

## 3. การไหลของข้อมูล (Data Flow)

```
ผู้เล่นกดปุ่ม (เช่น "ทิ้งไพ่")
   │  client/js/app.js
   ▼
ส่ง action ผ่าน socket ──────────► server/socket/handlers.js
                                       │ เรียก
                                       ▼
                                  server/game/round.js  (ตรวจถูกกติกาไหม + อัปเดต state)
                                       │
                                       ▼
                                  server/game/playerView.js  (สร้าง view ราย player)
                                       │ emit กลับ (ซ่อนไพ่ลับ)
   ◄───────────────────────────────────┘
client/js/render.js  วาดหน้าจอใหม่ให้ทุกคน
```

> 🔑 game logic อยู่ที่เซิร์ฟเวอร์ทั้งหมด — client เชื่อเซิร์ฟเวอร์เสมอ กันโกง

## 4. เครื่องมือ / Dependencies

| เครื่องมือ | ใช้ทำอะไร | ติดตั้ง |
|-----------|----------|--------|
| **Node.js** | รันเซิร์ฟเวอร์ (ภาษา JS) | ติดตั้งจาก nodejs.org |
| **express** | เสิร์ฟไฟล์ client + HTTP | `npm i express` |
| **socket.io** | real-time ระหว่างผู้เล่น | `npm i socket.io` |
| **node:test** | ทดสอบ game logic (มากับ Node ไม่ต้องลงเพิ่ม) | — |
| **nodemon** *(dev)* | รีสตาร์ทเซิร์ฟเวอร์อัตโนมัติตอนแก้โค้ด | `npm i -D nodemon` |

### คำสั่ง npm (ตั้งใน package.json)
| คำสั่ง | ทำอะไร |
|-------|--------|
| `npm start` | รันเซิร์ฟเวอร์ |
| `npm run dev` | รันแบบ auto-restart (nodemon) |
| `npm test` | รันชุดทดสอบ game logic |

## 6. การ Deploy แบบฟรี $0 (เล่นกับเพื่อน — ไม่มี cost)

**เป้าหมาย:** ฟรี 100% · รองรับ WebSocket (Socket.IO) · ส่งลิงก์ให้เพื่อนเล่น

| ส่วน | ใช้ | ฟรี? |
|------|-----|------|
| Host เกม (Node+Socket.IO+client แอปเดียว) | **Koyeb** (free nano, WebSocket, ไม่ต้องใช้บัตร) | ✅ |
| เซฟ state กันหาย | **Postgres ฟรีของ Koyeb** (หรือ Neon/Supabase/Upstash Redis) | ✅ |
| โดเมน | URL ฟรี `*.koyeb.app` | ✅ |

**วิธี (ตอนเฟส deploy):** push โค้ดขึ้น GitHub → ต่อ Koyeb กับ repo → auto-deploy → ได้ลิงก์ส่งเพื่อน

**ข้อแลกเปลี่ยนของฟรี (ยอมรับได้):**
- free tier **หลับเมื่อไม่มีคนเล่น** → เปิดครั้งแรกรอ ~30–60 วิ (cold start)
- หลับ/รีสตาร์ท → state ใน RAM หาย → **แก้ด้วยเซฟลง Postgres ฟรี + reconnect โหลดกลับ** (M7)
- มีได้ 1 service (เราใช้แอปเดียวพอดี)

> ตัวสำรอง: Fly.io, Render+UptimeRobot(กันหลับ) — *free tier เปลี่ยนบ่อย เช็คล่าสุดตอน deploy จริง*

- เสิร์ฟ client จากเซิร์ฟเวอร์เดียวกัน (ไม่ต้องแยก host)
- ขยายเป็น React ทีหลังได้ (เปลี่ยนแค่ `client/`) โดย game logic ไม่ต้องแก้
